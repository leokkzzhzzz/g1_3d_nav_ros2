# botbrain (G1 navigation source)

This is the **G1-machine snapshot** of the botbrain workspace — the
ROS 2 source for `bot_navigation` (Nav2 wrappers), `bot_bringup`
(twist_mux launch + zero_vel_publisher), `g1_pkg` (g1_write_node and
the G1 SDK control bridge), and the supporting custom-interface /
state-machine / sensor packages.

It came from the `botbrain_project-main.zip` tarball deepglint shared
with the project, then has accumulated whatever changes the team has
applied on the G1 itself (the most consequential one is documented
in ADR D-009: `g1_pkg/config/nav2_params.yaml` was forked to point at
this stack's `/map_2d` and `/cloud_registered_body_1` topics, and
later to use `body` instead of `base_footprint` as `robot_base_frame`).

This directory is the source of truth for what's actually running on
the robot, **not** upstream botbrain. If the upstream project
publishes a new release we'll merge selectively rather than overwriting
our G1-specific changes.

## Relationship with the running container

The runtime container `3d_nav_ros2` bind-mounts the host directory
`/home/unitree/botbrain_ws/` into the container as `/botbrain_ws/` —
this gives nav2 access to `install/<pkg>/` (compiled binaries) at
runtime. That mount **is not** the same as this `botbrain/src/`
directory in canon. The relationship is:

```
       canon repo                          G1 host                          container
       ──────────                          ───────                          ─────────
botbrain/src/<pkg>/                ←(reference)→  /home/unitree/botbrain_ws/         →  /botbrain_ws/
                                   (manual sync)        botbrain_project-main/
                                                          botbrain_ws/src/<pkg>/
                                                        (this is what colcon builds)
                                                        install/<pkg>/         →  /botbrain_ws/install/<pkg>/
```

I.e. the canon `botbrain/src/` is the **versioned snapshot**.
`/home/unitree/botbrain_ws/...` is the **build root** colcon uses,
and it's also what gets bind-mounted into the container so that
`install/` is visible at runtime.

If you change a botbrain source file and need it to take effect at
runtime, the workflow is:

```bash
ssh unitree@192.168.100.30
cd /home/unitree/botbrain_ws/botbrain_project-main/botbrain_ws

# 1. apply your edit there (the build-root copy)
$EDITOR src/<pkg>/...

# 2. rebuild the affected package
source /opt/ros/humble/setup.bash
colcon build --packages-select <pkg>

# 3. restart the relevant launch (g1_write_node etc.) so it picks up
#    the new install/<pkg>/lib/...

# 4. once you're happy, mirror the change into canon for version control
cp -r src/<pkg> /home/unitree/g1_3d_nav_ros2_repo/botbrain/src/
cd /home/unitree/g1_3d_nav_ros2_repo
git add botbrain/src/<pkg> && git commit -m "botbrain: <what you changed>" && git push
```

The two-step (build root edits run first, canon mirror runs later) is
intentional: it lets you iterate at runtime without paying the
git-commit ceremony for every prototype, and it lets you decide
which iterations are worth versioning.

## Future direction (R-006)

Roadmap R-006 considers upstreaming back to botbrain proper — once
the G1-specific patches (D-009 nav2_params forks, R-001
zero_vel_publisher activation) are stable enough, propose them as PRs.
Until that lands, canon's `botbrain/src/` is divergent from upstream
and **that's intentional**.
